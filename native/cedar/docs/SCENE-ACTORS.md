# Actual scene placement to actor/draw ownership

`SceneActors` owns an ActorRenderPoses and ActorWorld pair wired together at construction. Caller explicitly selects their shared axes. It connects actual parsed SceneResourceView placements to real ready draw resources via explicit producer callbacks; it does not create a scene, actor handle, model name, camera, yaw, scale or placement. Source-informed dependencies carry GPL-3.0-only notices and the retained New Yokosuka license/pin documented in SCENE-RESOURCE.md and ACTOR-WORLD.md; this composition incorporates no generated corpus or game bytes.

`add(view,index,key,camera,services)` selects an actual parsed record. Caller supplies a real nonzero actor-instance handle/four-byte code, actual finite cameraVP and two callbacks. Converter receives the actual placement (including source position/angle presence and original property offsets) and must return actual converted world position/yaw plus the model's baked reference position/yaw. It must reject unsupported orientation/scale/pitch/roll rather than discard fields or infer absent yaw. Resolver receives the same record and supplies actual ready mutable draw spans plus its resolved model filename identity. Complete filename bytes must exactly equal the record's model bytes; no tag-only match, hashing, case normalization or invented extension exists. Model/pixel identity remains the actual loader's responsibility, not authenticated merely by echoing a filename.

Up to64 actors are retained. Add validates source strings, finite camera/pose, caller handles, duplicate instance identity, draw count/ranges/ready resources through ActorRenderPoses, and overlap with the entire SceneActors object, view/placement records, model/image strings, caller key/camera/services and exact model identity. All view record/string spans are protected against output draw writes. Render owner additionally rejects overlapping registered draw spans and incompatible existing normal rotations. Underlying SceneResourceView bytes hidden by its API and callback context full extents remain caller disjointness/lifetime contracts; exposed pointers alone cannot prove arbitrary dangling pointers safe.

Converter/resolver are invoked under a busy guard; callback failures add no actor or render owner. World registration occurs first; render registration then validates and commits actual matrices/normal rotation atomically. If render fails, world registration is explicitly rolled back. A failed rollback retains a tracked world-only entry with rollback_pending, never an untracked registered actor. Results report world/render diagnostics and actual retained stage flags. Converter/resolver may do loader work externally; their side effects are not rolled back by this class and must follow caller ownership policy.

`facing_services()` routes real GameEventFacing calls through the owned world and its matching render pose callbacks. This reaches actual draw fields for ready resources, not just a queued identity. `read` exposes actual world state; mutable owner objects are intentionally not exposed. Placement metadata is copied per registered entry but model/image spans remain borrowed immutable source bytes. Keep placements, model resources, ready mesh/texture objects, draw spans and callback contexts valid for their relevant lifetimes. Initial callback contexts need only live through add; returned resources/identity spans remain valid until close. Serialize every operation and prohibit callbacks from mutating any owned world/render/component/source data directly.

`close()` tears down reverse registration order: clear/unregister actual world first, then restore current base pose/unregister render, then remove the receipt. GPU unavailable during clear or render unregister is a real retryable failure; the exact remaining world/render stage stays tracked and count is nonzero. No silent receipt loss or destructor call through borrowed GPU resources occurs. Restore ready resources before retrying close. Some entries may already have closed successfully; result.remaining is authoritative. A world-only retry entry is also removed through close. The SceneActors object must outlive its exported callbacks and remain alive until close succeeds with count0; close any GameEventFacing scene binding/host/context users first, then close SceneActors, then release GPU draws/resources and borrowed placement bytes.

No main loop, game scene selection, audio, original story event, runtime/tests, game assets or worker compilation is included. This is an actual ownership/registration chain available to a real startup producer, not evidence a scene has been loaded or played. Lead owns batch compilation and producer integration.

`resolve_tag` compares the original four placement.object_tag bytes exactly and returns the actual caller-supplied GameActorKey only for one fully world+render registered receipt. Multiple matches are ambiguous, never first-wins; a sole partial rollback/close receipt is unavailable, no match is missing. GameActorKey.code is never inferred from the tag. Both tag lookup and read reject busy callback observation as reentrant; outside callbacks read may expose a tracked world-only rollback receipt, while tag resolution deliberately withholds it from complete scene binding.
