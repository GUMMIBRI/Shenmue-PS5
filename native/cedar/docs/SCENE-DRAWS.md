# Actual MT5 resource to renderer binding

`assemble_mt5_scene_draws` creates real GpuDraw records from a complete successful MT5 expanded triangle extraction, corresponding ready GpuMesh, explicit ready texture bindings, actual camera and explicit per-draw material/light policy. It does not load a default scene, upload resources, infer camera/UV/color/normal values, fabricate a white texture or copy game data. Original assembly code uses existing source-informed readers; their retained format provenance remains in MT5/model-texture documentation.

## Exact texture and geometry linkage

The supplied Mt5TextureTable must be the actual table for this model. Its proven index policy is embedded TEXN IDs in encounter order, then NAME IDs in stored order. Source strip `texture_index` selects that exact index; opaque TEXL/PTRL metadata is never remapped. Caller provides a strictly increasing, unique explicit mapping from model texture index to opaque eight-byte ID and actual ready GpuTexture. Each mapping is checked through table.texture and exact byte identity; every referenced strip must find its binding. Caller package/texture provenance indices are copied without pretending to reauthenticate GPU pixel contents. Actual uploaded image-to-ID provenance is caller pipeline responsibility.

The source record sequence must describe contiguous, nonoverlapping expanded triangle ranges starting at zero and covering the ready mesh exactly. Each count is nonzero/divisible by3 with triangle_count equal to count/3, and all ranges fit the mesh. No winding reversal, degeneracy cleanup or triangle generation occurs here. Source node/strip/command/opaque words, UV flags, raw attribute spans and original texture index survive in SceneDrawBinding. Those spans remain borrowed immutable model storage. This facility cannot prove arbitrary records or uploaded bytes came from the same extraction; caller must supply actual successful corresponding producer outputs.

## Material and ready-resource contract

Every per-draw material must exactly match the selected fixed GpuRenderer pipeline configuration. Mixed blend/depth/cull/front-face/lighting/output policies are rejected; caller partitions actual material groups before assembly. Each alpha declaration must explicitly match opaque/straight/premultiplied pipeline policy. This is a producer assertion, not an inferred property of texture alpha or source opaque words. Texture, vertex and output transfer tags must be known explicit SDR choices. No source material interpretation is guessed.

Lit mode requires ready normal stream, supported RGBA/BGRA8 native SRGB versus UNORM texture semantics, explicit valid linear-light ambient/diffuse/direction, proper optional normal rotation and the renderer's target/alpha restrictions. Native SRGB samples decode before filtering; perceptual texture tag must match native SRGB format. Premultiplied lit mode is unsupported. Unlit preserves the existing shader's direct sampled×vertex behavior; transfer declarations record caller policy and do not enable new conversion. Caller must choose material/vertex encodings suitable for that existing pipeline, including any native sampler/target conversion. Assembly does not silently improve or linearize legacy unlit math.

All supplied texture mappings, including unused entries, must be real ready resources on the mesh's nonnull GPU device with actual buffer/texture/sampler handles. Pending/reset resources are unavailable; null pointers/bad devices/ranges are errors. Caller owns C++ resource lifetimes; readiness checks cannot make dangling objects safe. Camera is finite/nonzero but its actual projection/coordinate meaning remains caller-owned. GpuRenderer/SceneTarget must be initialized with the same selected pipeline; this function does not mutate renderer configuration or promise native driver support.

## Atomic caller-buffer assembly

Limits:1..4096 draw records,1..65536 sorted texture mappings. Output capacities are checked in full, not only written prefixes. Source records, texture/material arrays, camera, table/mesh/config objects and both output-capacity spans must be valid, aligned, nonwrapping and pairwise disjoint. Every raw attribute span and referenced texture object must be disjoint from outputs. Validation completes before the first output write; on any error written remains zero and both outputs are untouched. No allocations or callbacks occur between preflight and commit.

Underlying bytes hidden inside Mt5TextureTable are not exposed by its API; caller must additionally keep all borrowed model/package bytes immutable and disjoint from outputs. Camera, materials, source metadata and GPU resources remain stable throughout assembly. SceneDrawBinding preserves package indices as caller provenance, not package resource ownership. Output GpuDraw spans can be registered with ActorRenderPoses using the real baked reference/current pose; do not register these fields with multiple pose owners. Retain source/raw metadata and resources through their respective consumers. Teardown follows clear ActorWorld→unregister pose owner→release draws/resources.

No runtime/tests/assets or worker compilation. Lead owns batch compilation and actual resource/startup integration; this delivers resource-to-draw bindings, not playable scene/story evidence.
