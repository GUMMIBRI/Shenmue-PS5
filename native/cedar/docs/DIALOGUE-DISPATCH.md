`decode_dialogue_receiver` additionally preserves source inline10/inlineFC versus queued classification, source state code0x6c for word0x14 and0x6d for other queued values, and bit flags naming observed handler metadata. Source handler ranges are0x28..31→0x0c161140,0x32..3b→0x0c16175c,0x8c..95→table0x0c2243a0, facing families→0x0c16188c,0x0d→0x0c161e54,0x0a/0x0f→0x0c161f22. No address is dereferenced, queued or treated as executable. A legal queued receiver without a supported action is **not** a successful native effect: resolve returns unsupported_action. Inline10/FC also have no invented world effect. Words outside unsigned12, except exactFC00, are invalid.

`resolve_dialogue_dispatch` requires caller-supplied actual WORLD-space facing-target vectors and participant code list, at most10 and11 entries respectively. No generated actor IDs/target coordinates are included. It checks complete spans, alignment, arithmetic and pairwise overlap with descriptors/output before writes; target components must be finite; participants must have four non-NUL bytes. Index0 is deliberately not shifted into the participant-control range. Missing caller data returns precise errors, output unchanged. These bounded float/code restrictions are stricter than JavaScript's permissive array/null handling.

The caller-facing target array must already contain actual WORLD coordinates, explicitly converted by its producer from source scene coordinates. Facing families produce a GameFacingRequest using those supplied world values. Participant-control descriptors retain the source native offset and require either an explicit confirmed_native_world_identity profile or a real native→world vector converter callback before a world GameFacingRequest is produced. Missing converter/profile returns converter_unavailable; failure/nonfinite result prevents output commit. The source axis remains native provenance metadata, not a guessed world rotation. The browser staging X-negation is never silently imported. Selected-participant requests need a real selected-participant owner and must not be passed as facing commands. Fixed participant offset is source algorithm data, not an actor placement or imported proprietary asset. Converter/context lifetimes and full extents are caller-owned, immutable/disjoint from input/output arrays and descriptors throughout the call; only context starting-address overlap can be checked by the opaque callback API. The converter must not reenter with aliased output or mutate source/input/output storage; it receives a local source vector and local temporary destination. Outputs commit only after conversion success. Selected-participant returns metadata with has_facing_request=false and requires a separate real lookup/selection service; no facing or no-op success is fabricated. No automatic registry lookup, pose command, audio/message execution or machine acknowledgement occurs; real service applied status remains mandatory.

No corpus, generated tables, recovered external C, game assets, emulator or runtime was used. No tests/worker compilation. Lead owns batch compilation, coordinate integration and actual host binding; unsupported native commands remain unavailable.
