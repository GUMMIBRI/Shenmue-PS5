# Explicit native game-service composition

`NativeGameContext` connects the actual configured `WorldClock`, bound `GameState`, running `DialogueMachine` and optional `GameEventFacing`/host services. It does not invent a scene, actor, story, clock epoch, native runtime ID, bank layout or original-event implementation. This GPL-3.0-only composition uses the authored New Yokosuka adaptations described by `DIALOGUE-MACHINE.md`, `GAME-STATE-API.md` and `GAME-EVENTS.md`, at source pin `b0df7f2720a7eecabce2e610fdedec35bf1243e3`. Full GPL is retained in `third_party/licenses/new-yokosuka-GPL3.txt`; clock's separate MIT provenance remains in `WORLD-CLOCK.md`. No game corpus is incorporated.

## Bindings and actual predicate data

Bind borrows all components and copies up to32 unique caller-supplied RuntimeClockBinding entries, with aligned array storage and runtime modes limited to unsigned8 (0..255). It requires a configured clock and a machine whose provider and context are both empty; it never replaces another provider. Mappings name logical year/month/day/day-number/hour/minute/second/second-of-day/nanosecond/phase/paused fields. These numbers are supplied policy, not claimed native IDs. Phase uses the actual WorldDayPhase enum ordering; caller must intentionally select that representation. Day numbers beyond exact double integer range return unresolved.

State-bank operand requests read the real GameState, including unknown/read-only storage policy; unknown state is not delegated to a fallback to manufacture a value. Mapped runtime requests read an actual clock snapshot. Unmapped runtime/actor/spatial requests may call the optional read-only fallback provider; absence remains unresolved. The expression module checks finite provider values. No world time advances during predicate reads or dialogue stepping. `advance_world(elapsed_ns, diagnostic)` is a separate explicit call and uses the clock's real checked elapsed-time operation.

Object extents are checked pairwise across the whole context, clock, state, machine and optional event binder. GameState's full borrowed mutable storage is required disjoint from every component. Binding input arrays/services cannot overlap the context they initialize. Opaque callback context starting addresses are checked against objects/state storage, but their full extents, referenced objects and route aliases remain an explicit caller contract: all callback data and borrowed route/storage must be valid and correctly disjoint. The full state-storage/component disjointness guard runs again before every step, clock advance and provider read, and after host callbacks. Thus an external bank rebind between frames is checked before component work. Caller must not mutate components/routes during a step/callback. Context/provider guards reject mutating reentry through this context; they cannot stop malicious direct component access.

## One actual effect per step

`step_dialogue(budget, optional_resolved_facing)` first requires budget1..4096 even when a host action is already pending, then invokes the actual machine, then handles at most one pending request, copied before callbacks:

- Decoded bank2 write applies through actual GameState and acknowledges only after write success.
- An explicit facing descriptor is accepted only for a pending native_command with matching token and command word. It calls real GameEventFacing; only applied is acknowledged. It does not decode native commands or invent actors.
- Other pending requests use an optional real host callback. Missing service is unavailable and preserves the pending request. Real host must supply a bounded offset exactly when the pending descriptor requires one. No implicit completion, message display, audio playback or event acknowledgement exists.

When no action is pending, missing predicate returns dialogue_blocked; decode/expression failures return dialogue_failure; invalid machine arguments/state map to matching context status. Normal completion and budget yield retain status ok plus the exact nested machine outcome. Clock advancement also checks provider ownership before mutation. Result separates `effect_applied` from `acknowledged` and includes machine/state/facing diagnostics. After any callback, provider ownership and pending token are checked again. A real applied effect followed by invalid offset, replaced pending state or failed machine acknowledgement latches faulted: further steps cannot duplicate the effect or pretend rollback. Failure/unavailable without effects leaves pending for retry; a host reporting failure after partial outside effects must implement its own retry-safe policy. A callback that changes machine/provider ownership also faults even if it reports failure. Callback supplied invalid enum results never count as applied.

`unbind()` removes only this context's provider/context pair. A different provider is a conflict and is never overwritten. If its context pointer no longer equals this context (including a machine reset), unbind safely detaches only local borrowed references and returns provider_conflict with bound()==false. If another function still retains this context pointer, unbind returns provider_conflict with bound()==true; caller must first remove that pointer deliberately. Pending actions can prevent machine provider removal; unbind then fails and retains every borrowed pointer. The context must remain alive until the pending action is resolved or the caller explicitly resets the machine and restores/removes the owned binding through an intentional recovery path. There is no destructor call into possibly destroyed borrowed components. Components and service contexts must outlive the bound context; bound() must become false before destruction, through successful owned-provider removal or safe conflict detachment. Fault recovery is explicit, never an automatic repeat of an uncertain effect.

This is composed source functionality, not engine boot or original story progression. Missing host actions remain missing. No runtime, tests, proprietary data, autonomous playback or worker compilation was performed; lead owns batch compilation/link and real producer binding.
