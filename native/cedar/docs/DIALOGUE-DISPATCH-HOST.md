# Actual numeric dialogue host binding

GPL-3.0-only composition of the source-informed numeric mappings in DIALOGUE-DISPATCH.md and actor services in GAME-EVENTS.md. Pinned authored source: brynnb/new-yokosuka `b0df7f2720a7eecabce2e610fdedec35bf1243e3`; complete GPL retained in `third_party/licenses/new-yokosuka-GPL3.txt`. No new source corpus, generated tables or original game data is incorporated.

`DialogueDispatchHost` copies up to10 finite actual WORLD targets and11 explicit four-byte participant codes into fixed owned arrays. Zero entries are allowed; missing command-specific entries remain unavailable. Bind validates full source spans/alignment/arithmetic/pairwise aliases, whole host/facing object disjointness and opaque callback context starting addresses. It copies no default actor/target data. Converter and service contexts remain borrowed: full object extents and referenced data must remain valid/disjoint from all host/profile/component/request storage, and immutable where read, through each call. Caller serializes bind/handle/unbind and keeps real facing/selection services alive.

Factory `context_services()` supplies the actual facing pointer and a GameContextServices host callback/context pair suitable for NativeGameContext.bind; caller may add its own separate expression fallback. Numeric resolution handles pending native_command or invoke_and_yield descriptors with nonzero token and no redirect requirement. Other pending request types are delegated only to an explicitly supplied real fallback, preserving its redirect response. The actual pending descriptor is copied before callbacks and diagnostics retain its exact token plus resolver/facing/selection results. It never directly acknowledges a machine token. NativeGameContext independently verifies token/ownership after the actual callback and acknowledges only applied results.

Known target/participant-control words resolve through the actual numeric resolver, then call actual GameEventFacing.apply. With ActorWorld facing_services wired to ActorRenderPoses pose_services, the resulting route is numeric command→resolved world request→actual facing owner→actual draw pose update. Only real applied service status yields applied. No active actor, mismatched participant or missing pose/service remains unavailable. Caller must register the actual scene actor and actual ready draw resources; this host creates neither. This is a service connection, not a booted original scene.

Participant offset uses the explicit native-vector converter or explicitly confirmed native/world identity profile; no silent browser basis conversion. Missing target/participant/converter, conversion failure or nonfinite output never falls through to a fallback that might fabricate success. Distinct selected-participant descriptors call an optional real selection service with token/descriptor; absent selection is unavailable and never switches the active facing actor implicitly.

Inline10/FC00 and unknown-but-valid unsupported actions can call the optional real fallback host. Absent fallback remains unavailable. Invalid numeric command words are not delegated. Other event/message/state requests use that same optional real fallback and retain its actual result; missing service remains unavailable. A fallback must perform actual supported work; no default successful/no-op handler exists. Real failures may have partial effects: the implementation cannot rollback world mutations, and caller services must report/retry safely.

Busy guards reject mutating callback reentry; the diagnostic marks attempted handle reentry. Services/converter must not mutate this host, profile, pending storage, underlying context/machine/routes or unrelated components during callbacks. Unbind is refused while busy and otherwise releases only this host's bindings; it cannot clear a NativeGameContext's borrowed host pointer. Teardown order: unbind NativeGameContext first, then this host, then real actor/pose resources. No destructor callbacks through possibly dead borrowed services.

No machine execution, audio device/playback, fabricated host acknowledgement, engine entry stub, runtime/tests/assets or worker compilation. Lead owns batch review/compilation and real engine producer integration.
