# Real actor pose to draw-state bridge

`ActorRenderPoses` is original rigid-transform integration for caller-supplied actual draws, not generated actor placement or a gameplay renderer. It supplies real `ActorPoseServices` callbacks for ActorWorld: applied means all registered draw matrices and normal rotations were updated, not a queued actor name. No GPU command is recorded or submitted here.

Caller explicitly selects `y_up_yaw_z_toward_x`, supplies a nonzero instance key/four non-NUL code bytes, real cameraVP, baked mesh reference position/yaw, current position/base yaw and a borrowed mutable contiguous GpuDraw span. Registration metadata is copied; draw storage remains borrowed and must stay alive, exclusively owned for pose fields and stable until unregister. Up to64 actors, each1..4096 draws; all draw spans must be mutually disjoint, aligned, nonwrapping and disjoint from the whole registry and registration descriptor. Nonidentity existing normal rotations are rejected rather than silently composed. Duplicate instance handles are rejected even if actor codes differ. Registration and every subsequent commit require actual ready mesh/texture objects, real buffer/texture/sampler handles, nonzero triangle-aligned draw ranges within the mesh, and a shared nonnull GPU device. All parts validate before any draw write. Pending/reset resources return unavailable; missing pointers or bad ranges/devices return invalid_argument. Mesh/texture memory lifetime remains caller responsibility: these checks do not make dangling C++ pointers safe.

For effective yaw (override if present, otherwise latest base), the rigid world delta is exactly `T(current_position) * RY(effective_yaw-reference_yaw) * T(-reference_position)`. Every draw receives `cameraVP * delta`; a +Z direction turns toward +X for positive yaw. The corresponding world normal rotation is RY only. Caller mesh vertices/normals must actually be baked in the supplied reference world pose; local vertices with guessed pivots are unsupported. No scale, skinning or coordinate flip is inferred.

`update_base_pose` supplies real owner movement/base yaw and preserves an active dialogue override. `update_camera` replaces the explicit camera and recomposes existing pose. Clear-yaw restores the **current** base yaw. Unregister restores the latest base pose first, then releases registry ownership; caller can preserve that actual draw state. All inputs/intermediates/output matrix components are checked finite/float-range before any draw or registry write. Finite angles reduce before subtraction to avoid overflow; invalid operations leave all registered state unchanged. Serialize operations and do not externally mutate/reallocate draw pose fields or this object while registered. Teardown order is clear the ActorWorld facing override, unregister the render actor while its GPU resources remain ready, then release/reallocate draws or GPU resources. Clear/unregister can fail if resources were reset early; restore valid ownership before retry. No background callbacks, allocation or destructor pose writes exist.

## Normal stream integration

GpuVertex stays24 bytes, separate normal stream stays12 bytes/vertex. GpuLighting now optionally supplies a column-major3x3 proper rotation. Unset means identity; lit renderer checks finite column dot products and determinant+1 within1e-4. Reflections, scales and guessed inverse-transpose transforms are rejected. The lit vertex shader normalizes original finite normals using max-component rescaling before rotation, avoiding extreme-input overflow. Fragment interpolation/normalization remains unchanged; cancelled normals stay ambient-only.

The lit vertex slot1 UBO is now **80 bytes**, superseding the earlier16-byte transfer block in GPU-LIGHTING.md: vec4 transfer flags followed by column-major mat4 normal rotation (std140 set1binding1). CPU always uploads identity when rotation is unset. Camera slot0 remains64 bytes; lit vertex num_uniform_buffers remains2, fragment resources unchanged. Perceptual vertex decoding still happens before interpolation. Unlit shader/layout/behavior remains unchanged, although pose matrix updates legitimately affect both renderer modes. Root shader builder must regenerate the same `lit_mesh_vert` array from the updated shader.

This integrates actual pose-owner yaw with actual draw data; it supplies no engine camera, scene, animation, actor IDs, collision, gameplay placement or story binding. No game/emulator source or assets were copied. No runtime, tests or worker compilation; lead owns batch shader/host/target compilation and human visual qualification.
