## Proven service bindings

An active scene actor requires a nonempty instance ID plus exactly four-character actor code. A descriptor actor mismatch or no active scene actor returns ignored, not applied. A facing-target descriptor requires exactly three finite scene coordinates and passes them to `setDialogueFacingTarget(instanceId, target, {activate,...})`; activation is true only when `appliesControlStateTransition` is exactly true. The service's false result returns unavailable.

A descriptor without facingTarget is accepted for participant control only when `participantRoute.behavior` equals `participantControlDispatch`, a motionPoint exists, and participantCode matches the active scene actor code. Its finite nativeOffset vector goes to `setDialogueFacingOffset(instanceId, offset, {activate:true,...})`. Source commandWord/index/handler/request addresses are carried as provenance metadata, not executed. End clears the scene actor's facing target. Both coordinate helpers negate X for Babylon/browser representation; that conversion is not evidence for the native renderer's world-coordinate convention.

Replacing an active scene first calls the real clear callback; failure preserves the old identity. `end` clears ownership only after actual clear success (stricter than the source's unchecked clear). There is no automatic destructor callback; caller must explicitly end while its service context is alive. Callback contexts/registries outlive this object; serialize all calls, do not mutate/reenter the binder from callbacks. A busy guard rejects mutating reentry. Callback failure after partial external effects must be handled by the real service's retry policy; this binder cannot undo world mutations. `dispatch_numeric` always returns unsupported_command. Successful facing operations alone may satisfy a matching already-resolved host request; they do not implement unrelated state/audio/message/native events.

## Why no numeric native dispatcher is delivered

The reviewed files do not map numeric command IDs to facingTarget or participantRoute descriptors. They receive those objects from upstream decoder/runtime logic. The typed facing binder therefore does not claim a real `commandWord -> world/state/audio/message` implementation; inventing IDs or treating an unknown native event as success would hide the missing semantics.

The precise next evidence needed is the interaction runtime's dispatch descriptor producer, including supported commandWord ranges, resource lookup, target coordinates, participant resolution and unsupported cases. That lies beyond the expanded three-file scope. A later finite task can inspect that specific producer under the same license boundary. Until then raw numeric dialogue-machine requests remain pending/unavailable; source-backed state-bank/runtime writes can bind only through their already explicit decoded contracts and real owner services.

This audit adds no actor IDs, game event data, native memory address execution, audio/message lookup, gameplay success claim or engine boot path. No runtime, tests, assets, compilation, external source corpus or emulator code was used. Stop condition reached: exact missing dispatch mapping isolated rather than guessed.
