# Native device session contract

`Ps5Session` is original composition code for the existing native input/audio,
SDL3 presentation, descriptor-relative assets, app-owned save storage, and
`Platform` frame lifecycle. It supplies all six real `Services` callbacks to an
owned `Platform`. It contains no game engine, entry point, fake boot, automatic
route, simulation, decoder or renderer implementation.

## Process and configuration ownership

The application must load its required public native modules and initialize its
user service, `Ps5Input::initialize_backend`, and
`Ps5AudioOutput::initialize_api` before starting this session. Check each actual
native result. Successful process initialization is asserted explicitly by
`Ps5SessionConfig::process_apis_ready`; it is a caller contract, not a verification
or an already-initialized error-code workaround. Session never initializes,
terminates, enumerates or silently selects process/user services.

Configuration requires a nonnegative selected user ID, mono/stereo 48 kHz float
audio and a grain of 256–2048 frames in multiples of 256, plus presentation
settings. Empty asset/save root fields disable those facilities. Nonempty roots
are explicit existing directories; the save root must be newly provisioned and
app-owned, never an original game's save directory. No directory is defaulted,
created, imported or migrated. Session mounting performs no save writes.

Start copies title (at most 255 bytes), renderer name (127), and both roots
(1023 each), rejecting overlong or embedded-NUL roots. Caller config string
storage can expire after start returns. The root backends retain their existing
no-follow/descriptor restrictions and their documented hard-link/privileged
actor limitations. Session does not establish ownership of a path on its own.

## Lifecycle and failures

Startup proceeds asset mount, save mount, pad open, audio open, presentation
initialization. A failure records its stage/native or structured storage error
then attempts cleanup of acquired resources. It never reports full rollback
merely because cleanup was attempted. Pad/audio close failures are retained in
sticky diagnostics, and `cleanup_pending()` reports handles still owned.

`shutdown()` stops frame processing, releases SDL presentation, attempts native
audio/pad closure, and unmounts storage. Repeated shutdown calls retry retained
native handles. The original operation failure and sticky close failures remain
available after cleanup. An explicit shutdown return reports whether native
handles remain; it does not erase earlier faults. Destruction is best effort:
call explicit shutdown first when cleanup failure needs to be observed.

Presentation teardown and existing storage `unmount()` interfaces return void.
Their failures cannot be surfaced by this composition. A future requirement for
observable descriptor-close errors needs changes to those backend interfaces;
this code does not claim they were checked. Process services remain app-owned.

`Platform` is one-shot: reconstruct the session after successful shutdown or a
device-start failure. Invalid configuration before actual startup can be fixed
and submitted again. All session operations, SDL presentation destruction,
storage use, and synchronous audio submission occur on one application video/
main thread. There is no audio worker or implied thread safety.

Suspend returns `unavailable` while ready and leaves all resources/frame state
unchanged. The current native close/open APIs cannot promise transactional
rollback if one device closes and another fails. Session therefore does not
claim a completed native suspend. Resume follows Platform state validation
(normally `invalid_state`, since no successful suspend occurred); the underlying
resume callback also returns `unavailable`. Neither callback fakes a device
transition.

## Frame and event ownership

`begin_frame(timing, input)` reads `clock_gettime(CLOCK_MONOTONIC)` and forwards the
timestamp to Platform, which polls actual pad state and computes button edges.
Clock errno and invalid/overflowing timestamps fail explicitly. Output timing/
input are cleared before attempts. Upload an application-produced `SurfaceView`,
then call `present()` to finish the opened frame. No surface is generated by the
session. Presentation failures preserve the underlying error string and
Platform's failed phase. Audio submits only in ready state, and queued submit
retains the existing consume-after-native-success contract.

Session does not poll or discard SDL events. The application owns the entire
event pump and every unhandled event. On its actual quit event or another user
quit request, call `request_quit()`; `quit_requested()` then remains true and new
frame beginnings fail. This is an explicit application notification, not
automatic OS quit detection. Finishing an already-open frame remains possible.

`assets()` returns a const mounted reader only while ready. `saves()` returns
the explicitly mounted app-owned store only while ready. Pointer validity ends
at shutdown; the caller must not retain and use either pointer across teardown.
The session does not automatically save, load or interpret blobs.
